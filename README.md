# LedgerPilot 网页对账机器人

在独立浏览器中读取订单和收款流水，保留来源页截图，按订单核对收款，再由业务人员处理差异。

打开网站后，「采集监视器」会回放最近一次已完成任务。时间线先展示真实采集页，再逐条呈现已保存的核对结果。可暂停、拖动进度条、切换 1× / 2× / 4× 速度，或直接从事件进入对应订单。点击「新建运行」将切换至实时采集。首次使用且没有历史任务时，首页展示当前来源预览，点击「开始对账」即可执行。

## 启动与演示

Windows 需要 Node.js 20 或以上，以及 Microsoft Edge 或 Google Chrome。解压整个交付包，双击 **启动工作台.cmd**。交付包已包含 Playwright Core，可以离线运行。仅复制源码时，启动器会通过 npm 安装锁定版本的依赖。也可以在项目目录执行 `npm start`，打开 http://127.0.0.1:47138。

1. 打开「数据来源」，点开订单页和流水页，观察分页表格。
2. 回到「对账工作台」开始运行。浏览器实际点击下一页、读取 DOM 并保存截图。点击「暂停任务」可在当前页处理结束后暂停，点击「从检查点继续」恢复。
3. 示例有 24 笔订单、24 笔流水。应得到 20 条匹配、5 条异常（2 条缺流水、1 条不足、1 条超额、1 条无订单流水），共 25 条结果。LP-26005 的两笔分次付款会合并核对。
4. 筛选「待复核」，查看详情，点开来源页截图，根据页面行号核实金额。填写复核说明后保存，保留原始差额与异常类别。
5. 导出 CSV 获取每单的金额、流水号、证据位置与复核说明。「运行历史」可以重新打开之前的报告。

## 自有数据

在「数据来源」下载两份样表并上传 UTF-8 CSV。订单表需要「订单号、客户、应收金额」，流水表需要「流水号、订单号、实收金额」。列顺序不限；订单号及流水号各自在自己的表内唯一，多笔不同流水可以归属同一订单。金额为非负数，最多两位小数，按人民币分核算。允许只有表头的单张空表。单表最多 2500 行。

导入的两张表会生成对应的本地业务网页。机器人读取启动时冻结的批次数据，后续导入只影响新运行。接入外部系统的自动登录、分页和写回，需要针对业务系统增加适配；本版处理订单核对及复核记录，不操作资金。

## 可选浏览器扩展

在 Edge 或 Chrome 的扩展管理页开启开发者模式，使用「加载解压缩的扩展」选择项目内的 `extension` 目录。打开可见的 HTML 表格，点击扩展图标，再点击「读取当前页」。选择订单或流水、映射三列，导出该页 CSV，然后导入工作台。可在本地示例源页面试用。扩展使用 activeTab 与 scripting 权限，由用户点击触发，读取范围为当前页面。虚拟列表、画布表格、跨域 iframe 需要业务适配。

## 实现与运维

- `server.mjs` 管理本机服务、业务页面、批次快照、任务状态、复核和导出。
- `lib/robot.mjs` 通过 Playwright 驱动 Chromium。采集失败最多再试两次。每页截图成功后保存数据和游标，重启后可继续。
- `lib/ledger.mjs` 实现 CSV 解析、分单位金额计算、分次收款合并和差异分类。
- `web/` 是中文工作台，`extension/` 是可选的浏览器采集扩展。
- 默认数据目录为 `local-data/`，内含导入数据、批次、日志、明文复核说明和 PNG 截图。请在适当权限的电脑上运行。分享素材时只使用示例数据。
- 默认仅监听 127.0.0.1。环境变量可调整运行位置：`LEDGER_PORT` / `PORT`（端口，云端优先用 `PORT`）、`LEDGER_HOST`（绑定地址，云端设 `0.0.0.0`）、`LEDGER_DATA`（数据目录，云端建议 `/tmp/ledgerpilot-data`）、`PUBLIC_BASE`（对外访问地址，用于跨站请求校验，Render 会自动注入 `RENDER_EXTERNAL_URL`）、`LEDGER_BROWSER`（本机浏览器程序路径）、`PLAYWRIGHT_BUNDLED=1`（改用 Playwright 自带 Chromium）、`AUTO_SEED=1`（启动后自动跑一次示例账期，避免首屏空白）。一个数据目录同时只供一个服务实例使用。
- 执行 `npm test` 会在临时目录和独立端口启动服务，通过真实浏览器验证完整流程，保留该次验收数据和截图，终端会输出路径。

本项目使用确定性金额规则，无需模型密钥。演示时可以直接展示网页采集、异常分流、断点续跑、浏览器扩展和可追溯的复核流程。

## 部署到云端

本地版本靠调用电脑上已装的 Edge/Chrome 跑，云端容器里没有这两个浏览器，所以必须换成 Playwright 自带的 Chromium。仓库已经做好双模式切换：本地走 Edge 不动，云端自动走内置 Chromium，靠 `PLAYWRIGHT_BUNDLED=1`（或 `NODE_ENV=production`）触发。

**为什么用 Docker 而不是普通 Node 运行时：** Chromium 除了可执行文件，还需要 `libnss3`、`libatk`、`libgbm` 等一批系统库，普通 Node 环境的构建阶段没有 root 权限装这些，会拖到运行时才崩。`Dockerfile` 基于 Playwright 官方镜像，这些依赖全都现成。

**Render 部署：**

1. 把仓库推到 GitHub。
2. Render → New → Blueprint，选中仓库，它会自动识别 `render.yaml`。
3. 等构建完成，打开分配到的域名。

`render.yaml` 里已经配好全部环境变量，`PUBLIC_BASE` 不用手填，Render 会注入 `RENDER_EXTERNAL_URL`。

**内存是唯一的坑。** Chromium 常驻大约占 300–500MB，Render 免费实例只有 512MB，大概率 OOM 重启。`render.yaml` 因此写的是 `plan: starter`。想先免费试可以把 `plan` 改成 `free`，能跑起来算运气，跑不起来别在上面耗时间。

**数据是临时的。** 云端 `LEDGER_DATA` 指向 `/tmp`，实例重启或重新部署后清空。`AUTO_SEED=1` 会让服务启动后自动跑一次示例账期，所以打开页面时已经有 20 条匹配、5 条异常可看，不会是一张白纸。真实业务数据不该放在这个演示实例上。

**本地不要随手跑 `npm install`。** `package.json` 里加了 `playwright`，安装它会额外下载一份 Chromium 到用户目录（约 150MB）。本地已经能借 Edge 跑，不需要它。真要装就带上 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`。

**本地验证部署配置**（不起容器也能测大部分逻辑）：

```bash
LEDGER_HOST=0.0.0.0 LEDGER_PORT=47990 PUBLIC_BASE=https://demo.onrender.com \
LEDGER_DATA=/tmp/lp-test AUTO_SEED=1 npm start
```

然后用 `curl -H "Host: demo.onrender.com" http://127.0.0.1:47990/api/state` 验证跨站校验放行，用 `-H "Host: evil.com"` 验证拒绝。
